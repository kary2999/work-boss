# 建設記錄：做了什麼

本文件記錄 work-boss 是怎麼被搭起來的，包含**走過的彎路**。它不包含任何工作日誌內容。維護者每次改動追加到「變更記錄」。

## 1. 起點

使用者要做一件事：為一個示範專案（一套 Axure 母版庫）每天排工作、收進度、沒做完就催。要求：

- 本地倉庫裡記錄工作內容，**多個 agent 可以協作**；
- 每天 08:30 告知今日工作，20:30 詢問進度，沒回覆就每 30 分鐘追問到 0 點，記旷工；
- 用 Lark 作溝通通道，和另一個已在使用該機器人的系統（Hermes）**共用同一個機器人而不能影響它**；
- 不要上傳工作日誌。

## 4. 技術發現（給後來者）

- **共用機器人不影響原系統的做法**：同一個 Lark 應用開第二條長連接，事件會被隨機分流，等於搶另一個系統的消息。所以本系統只用 REST，不訂閱事件。
- **「回覆指定消息」可行**：消息列表返回 `parent_id`／`root_id`，可據此判斷某條回覆指向哪個提問；讀群消息需要 `im:message.group_msg`。
- **原生「投票」沒有開放接口**：沒找到給應用發起投票的接口；卡片的勾選器若要把結果傳回，必須走回調。本系統因此用「Lark 任務／子任務勾選」做多選，由輪詢讀取。
- **任務 v2 能做到**：建任務、建子任務、改標題／描述／起止時間、讀完成狀態與評論，全部用應用身份（tenant token）。
- **launchd 與外接卷**：用戶級 launchd 任務可讀家目錄，不可讀 `/Volumes/…`（`Operation not permitted`）。
- **頁面縮放**：從 H5 頁面讀 CSS 尺寸時要注意頁面本身可能有縮放，對標前先確認換算。

## 5. 現在的狀態與未決

- 已具備：確定性監工腳本、32 個單元測試、launchd 模板與安裝自測、自動刷新的看板、進度回寫本地、次日計畫維護、需求不足主動要需求、私有資料檢查。
- 未實測（需要真實環境走一遍）：launchd 安裝後的完整一天（取決於倉庫位置與權限）、早間「順延項改期」在真實 Lark 上的表現。
- 待補：使用說明用截圖（見 docs/usage.md）。
- 未做：多人／多群、任務完成後的自動回寫任務卡、與 issue tracker 的對接。
