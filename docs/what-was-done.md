# 建设记录：做了什么

本文件记录 work-boss 是怎么被搭起来的，包含**走过的弯路**。它不包含任何工作日志内容。维护者每次改动追加到“变更记录”。

## 1. 起点

用户要做一件事：为一个示范项目（一套 Axure 母版库）每天排工作、收进度、没做完就催。要求：

- 本地仓库里记录工作内容，**多个 agent 可以协作**；
- 每天 08:30 告知今日工作，20:30 询问进度，没回复就每 30 分钟追问到 0 点，记旷工；
- 用 Lark 作沟通通道，和另一个已在使用该机器人的系统（Hermes）**共用同一个机器人而不能影响它**；
- 不要上传工作日志。

## 4. 技术发现（给后来者）

- **共用机器人不影响原系统的做法**：同一个 Lark 应用开第二条长连接，事件会被随机分流，等于抢另一个系统的消息。所以本系统只用 REST，不订阅事件。
- **“回复指定消息”可行**：消息列表返回 `parent_id`／`root_id`，可据此判断某条回复指向哪个提问；读群消息需要 `im:message.group_msg`。
- **原生“投票”没有开放接口**：没找到给应用发起投票的接口；卡片的勾选器若要把结果传回，必须走回调。本系统因此用“Lark 任务／子任务勾选”做多选，由轮询读取。
- **任务 v2 能做到**：建任务、建子任务、改标题／描述／起止时间、读完成状态与评论，全部用应用身份（tenant token）。
- **launchd 与外接卷**：用户级 launchd 任务可读家目录，不可读 `/Volumes/…`（`Operation not permitted`）。
- **页面缩放**：从 H5 页面读 CSS 尺寸时要注意页面本身可能有缩放，对标前先确认换算。
