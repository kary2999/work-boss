# 使用說明

本頁說明「一天裡你會看到什麼、要做什麼」。截圖位預留在 `docs/assets/`，僅放使用者同意公開的畫面。

## 一天的節奏

| 時間 | 你在群裡會看到 | 你要做什麼 |
|---|---|---|
| 08:30 | 橙色卡片「今日工作項」：表格（時段／任務／估時／子任務數／連結） | 打開任務，按時段做；做完在 Lark 勾選 |
| 做事過程中 | 無 | 完成就勾選（主任務、子任務都可）；做不完在**任務評論**寫原因 |
| 20:30 | 「今日進度詢問」：綠（全完成）／橙（部分）／紅（無證據），表格含每項狀態 | 把還沒勾的處理掉；或在評論寫原因 |
| 21:00–23:30，每 30 分鐘 | 紅色「第 N 次催促：請點擊完成」（只列未完成且沒說明的） | 勾選完成，或寫評論；寫了就不再催 |
| 00:00 | 「昨日收尾」：完成度、旷工與否、順延清單、今日草案前幾項 | 看一眼；有疑問在任務評論說 |
| 次日 08:30 | 順延項會**改期到今天**（不是新建），排在最前；任務描述不會被覆蓋 | 照常做 |
| 白天（每小時） | 沒有消息；本地看板、任務卡進度、次日計畫草案在背景更新 | 隨時打開看板看最新 |
| 發現明天（或今天）工作量太少 | 橙／紅色卡片「明日需求不足」：列出已排項與工時、低於下限多少、怎麼補 | **對卡片點「回覆」，每行寫一條需求**，可寫「2h」；沒寫估時默認 1h |

## 「需求不足」怎麼補

監工算出某天的計畫工時低於下限（默認 4h）就會主動問你要需求：

| 補法 | 做法 | 結果 |
|---|---|---|
| **回覆卡片（最快）** | 對卡片點「回覆」，每行一條，例：`畫導航欄 2h`、`整理圖標`（沒寫估時按 1h） | 下次監工運行（最遲一小時內）讀取，併入該日計畫，排在現有時段之後 |
| 新增任務卡 | 在 `tasks/` 複製 `_TEMPLATE.md`，**一定要寫 `est_hours`** | 進入 backlog，補進次日計畫 |
| 讓 agent 寫計畫 | 寫 `plans/日期.json`，把 `generated_by` 設為 `human` | 監工不會覆蓋，只會追加你的補充需求 |

同一天最多主動要 3 次、兩次至少隔 90 分鐘，00:00 收尾還會再要 1 次。

## 看板（自動刷新）

`docs/dashboard.html` 在**每個監工命令結束時自動重新生成**，不用手動跑。有五個分頁：

| 分頁 | 內容 |
|---|---|
| 概覽 | 今日主任務（來自 Lark 勾選）、明日計畫工時與「需求不足／超載／草案」、旷工、你補充的需求 |
| 進度 | 每天一張表：每個任務是否完成、子任務進度、你寫的未完成原因、催促次數 |
| 計畫 | 每天的計畫（時段、估時、順延、來源），低於下限會標紅 |
| 任務卡 | `tasks/` 的卡片，含從 Lark 同步回來的 `progress` |
| 日誌 | `worklog/` 全部日誌，可篩選 |

頁面頂部會顯示「資料生成於 …」，那是最近一次監工運行的時間。

## 你可以怎麼回應

| 動作 | 效果 |
|---|---|
| 勾選主任務 | 計為完成；停止對它的催促 |
| 勾選子任務 | 計入子任務進度（x/y），不影響主任務完成判定 |
| 在任務**評論**寫原因 | 計為「有說明」；不再催；仍會順延；不算旷工 |
| 對監工的提問卡片點「回覆」 | 計為已回報；當晚停止追問 |
| 什麼都不做 | 每 30 分鐘催到 23:30，00:00 記旷工並順延 |

## 手動命令

```bash
python3 scripts/supervisor.py status               # 今日任務與提問狀態
python3 scripts/supervisor.py morning --dry-run    # 預覽將建立的任務與卡片
python3 scripts/supervisor.py sync                 # 立刻同步進度、次日計畫、看板
python3 scripts/build_dashboard.py                 # 只重新生成看板（不讀 Lark，用最近一次同步的資料）
```

看板是靜態 HTML，資料在生成時嵌入；重新生成後要刷新頁面才看到新內容。
