# 使用说明

本页说明“一天里你会看到什么、要做什么”。截图位预留在 `docs/assets/`，仅放用户同意公开的画面。

## 一天的节奏

| 时间 | 你在群里会看到 | 你要做什么 |
|---|---|---|
| 08:30 | 橙色卡片“今日工作项”：表格（时段／任务／估时／子任务数／链接） | 打开任务，按时段做；做完在 Lark 勾选 |
| 做事过程中 | 无 | 完成就勾选（主任务、子任务都可）；做不完在**任务评论**写原因 |
| 20:30 | “今日进度询问”：绿（全完成）／橙（部分）／红（无证据），表格含每项状态 | 把还没勾的处理掉；或在评论写原因 |
| 21:00–23:30，每 30 分钟 | 红色“第 N 次催促：请点击完成”（只列未完成且没说明的） | 勾选完成，或写评论；写了就不再催 |
| 00:00 | “昨日收尾”：完成度、旷工与否、顺延清单、今日草案前几项 | 看一眼；有疑问在任务评论说 |
| 次日 08:30 | 顺延项会**改期到今天**（不是新建），排在最前；任务描述不会被覆盖 | 照常做 |
| 白天（每小时） | 没有消息；本地看板、任务卡进度、次日计划草案在背景更新 | 随时打开看板看最新 |
| 发现明天（或今天）工作量太少 | 橙／红色卡片“明日需求不足”：列出已排项与工时、低于下限多少、怎么补 | **对卡片点“回复”，每行写一条需求**，可写“2h”；没写估时默认 1h |

## “需求不足”怎么补

监工算出某天的计划工时低于下限（默认 4h）就会主动问你要需求：

| 补法 | 做法 | 结果 |
|---|---|---|
| **回复卡片（最快）** | 对卡片点“回复”，每行一条，例：`画导航栏 2h`、`整理图标`（没写估时按 1h） | 下次监工运行（最迟一小时内）读取，并入该日计划，排在现有时段之后 |
| 新增任务卡 | 在 `tasks/` 复制 `_TEMPLATE.md`，**一定要写 `est_hours`** | 进入 backlog，补进次日计划 |
| 让 agent 写计划 | 写 `plans/日期.json`，把 `generated_by` 设为 `human` | 监工不会覆盖，只会追加你的补充需求 |

同一天最多主动要 3 次、两次至少隔 90 分钟，00:00 收尾还会再要 1 次。

## 看板（自动刷新）

`docs/dashboard.html` 在**每个监工命令结束时自动重新生成**，不用手动跑。有五个分页：

| 分页 | 内容 |
|---|---|
| 概览 | 今日主任务（来自 Lark 勾选）、明日计划工时与“需求不足／超载／草案”、旷工、你补充的需求 |
| 进度 | 每天一张表：每个任务是否完成、子任务进度、你写的未完成原因、催促次数 |
| 计划 | 每天的计划（时段、估时、顺延、来源），低于下限会标红 |
| 任务卡 | `tasks/` 的卡片，含从 Lark 同步回来的 `progress` |
| 日志 | `worklog/` 全部日志，可筛选 |

页面顶部会显示“数据生成于 …”，那是最近一次监工运行的时间。

## 你可以怎么回应

| 动作 | 效果 |
|---|---|
| 勾选主任务 | 计为完成；停止对它的催促 |
| 勾选子任务 | 计入子任务进度（x/y），不影响主任务完成判定 |
| 在任务**评论**写原因 | 计为“有说明”；不再催；仍会顺延；不算旷工 |
| 对监工的提问卡片点“回复” | 计为已回报；当晚停止追问 |
| 什么都不做 | 每 30 分钟催到 23:30，00:00 记旷工并顺延 |

## 手动命令

```bash
python3 scripts/supervisor.py status               # 今日任务与提问状态
python3 scripts/supervisor.py morning --dry-run    # 预览将建立的任务与卡片
python3 scripts/supervisor.py sync                 # 立刻同步进度、次日计划、看板
python3 scripts/build_dashboard.py                 # 只重新生成看板（不读 Lark，用最近一次同步的数据）
```

看板是静态 HTML，数据在生成时嵌入；重新生成后要刷新页面才看到新内容。
